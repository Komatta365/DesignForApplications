## 結論

複数の頭身で同じモーションを共有できます。むしろ、2頭身、3頭身、4頭身、6頭身、7頭身などを扱う場合は、モーションと体型比率を分離する設計をおすすめします。

```text
モーション
    ↓
Normalized Skeleton
    ↓
頭身変換
    ↓
DWPose PNG
```

この構成にすると、1つの歩行や攻撃モーションから、各頭身に合わせたSkeletonと制御画像を生成できます。

## 頭身ごとにモーションを作らない

次のように、頭身ごとのモーションを個別に管理すると、後から修正するときに同じ変更をすべてへ反映する必要があります。

```text
Walk_2Head
Walk_3Head
Walk_4Head
```

歩行、走行、攻撃、待機などのモーションが増えるほど、管理対象も増え続けるため、この設計はおすすめできません。

## 推奨設計

### モーションは頭身を持たない

モーションデータには体型ではなく、左右の腕や脚の動きだけを保存します。

```json
{
  "motion": "walk",
  "frame": 3,
  "left_leg_forward": 1.0,
  "right_leg_forward": -1.0,
  "left_arm_forward": -0.8,
  "right_arm_forward": 0.8
}
```

これは再利用可能なアニメーション指示であり、最終的な骨の長さやキャラクターの頭身を含みません。

### Normalized Skeletonを使う

Normalized Skeletonでは関節位置を比率座標で管理します。

```json
{
  "hip": [0.5, 0.5],
  "head": [0.5, 0.15],
  "left_ankle": [0.4, 0.9],
  "right_ankle": [0.6, 0.8]
}
```

この骨格自体には「何頭身か」という情報を持たせません。共通のモーションを適用した中間表現として扱い、次段階でBody Styleを適用します。

## Body Styleを適用する

頭身ごとの体型比率は、モーションとは別の設定として定義します。

### 7頭身

```json
{
  "head": 1.0,
  "torso": 3.0,
  "leg": 3.0
}
```

### 4頭身

```json
{
  "head": 1.2,
  "torso": 1.4,
  "leg": 1.4
}
```

### 2頭身

```json
{
  "head": 1.0,
  "torso": 0.4,
  "leg": 0.6
}
```

## BodyStyle JSON

骨ごとの倍率を指定する場合は、次の形式を使用できます。

```json
{
  "id": "chibi_2head",
  "head_scale": 2.0,
  "torso_scale": 0.50,
  "upper_arm_scale": 0.70,
  "forearm_scale": 0.70,
  "thigh_scale": 0.60,
  "shin_scale": 0.60
}
```

腕と脚を部位別に分けることで、上腕・前腕・大腿・下腿を個別に調整できます。

## スプライト向けBody Style

スプライト用途では、全身の比率を割合で管理する形式も扱いやすくなります。

```json
{
  "body_style": "chibi",
  "head_ratio": 0.50,
  "torso_ratio": 0.20,
  "leg_ratio": 0.30
}
```

比率の合計を1にすることで、キャラクターの描画範囲に対する各部位の長さを統一して扱えます。

## まとめ

この設計では、同じ歩行モーションを2頭身、3頭身、4頭身、7頭身のキャラクターで再利用できます。

ゲームエンジンの概念に近づけると、次の関係です。

```text
Animation Clip
    +
Avatar / Body Style
```

KImageGraphでは、モーションと頭身を分離することで、次の利点があります。

- モーションの修正を1箇所で管理できる
- キャラクター固有の頭身をBody Styleとして追加できる
- 歩行、走行、攻撃などを体型別に複製しなくて済む
- 将来的にモンスターや非人型キャラクターへ拡張しやすい
- DWPose PNGの生成工程を共通化できる

特に、複数のキャラクターへ同じアニメーションを展開する場合は、頭身ごとのモーションを作るよりも、Normalized SkeletonとBody Styleを組み合わせる方が保守性が高くなります。

## 頭身変換の計算式

KImageGraphでは、モーションの向きと、体型に応じた骨の長さを分離するため、ボーン長スケール方式を使用するのがおすすめです。

### 正規化骨格

まず、モーション側では特定の頭身を持たない正規化値を定義します。

```json
{
  "pelvis": [0.5, 0.5],
  "spine_length": 1.0,
  "upper_arm": 1.0,
  "forearm": 1.0,
  "thigh": 1.0,
  "shin": 1.0
}
```

各ボーンの方向はモーションから取得し、長さはBody Styleで決定します。

### BodyStyle定義

#### 7頭身

```json
{
  "name": "7head",
  "head": 1.0,
  "spine": 3.0,
  "upper_arm": 1.0,
  "forearm": 1.0,
  "thigh": 1.5,
  "shin": 1.5
}
```

#### 4頭身

```json
{
  "name": "4head",
  "head": 1.2,
  "spine": 1.5,
  "upper_arm": 0.8,
  "forearm": 0.8,
  "thigh": 1.0,
  "shin": 1.0
}
```

#### 2頭身

```json
{
  "name": "2head",
  "head": 2.0,
  "spine": 0.5,
  "upper_arm": 0.6,
  "forearm": 0.6,
  "thigh": 0.7,
  "shin": 0.7
}
```

これらは基準ボーンに対する倍率として扱います。

## ボーン計算

肩から肘への方向を正規化ベクトルで表すと、次のようになります。

```text
direction = normalize(elbow - shoulder)
elbow = shoulder + direction × upper_arm_length
```

一般式は、親関節の位置を`P`、方向ベクトルを`D`、ボーン長を`L`とすると、次の式です。

```text
Child = P + normalize(D) × L
```

Body Styleの倍率を含めると、子関節の位置は次のように計算します。

```text
BonePosition(child)
    = BonePosition(parent)
    + normalize(direction)
    × BaseBoneLength
    × BodyStyleScale
```

この式により、同じ方向を持つモーションでも、キャラクターの体型に応じた関節位置を求められます。

### 頭身変換の例

正規化骨格が次の連結関係を持つ場合を考えます。

```text
hip
 ↓
spine
 ↓
neck
 ↓
head
```

7頭身を基準とした長さの例です。

```text
head  = 100
spine = 300
leg   = 300
```

2頭身では、頭を大きくし、胴体と脚を短くします。

```text
head  = 200
spine = 80
leg   = 120
```

ボーン長の基本変換式は、次のとおりです。

```text
scaled_length = base_length × body_style_scale
```

### KImageGraph用BodyStyle Schema

実装では、ボーン種別ごとに倍率を設定します。

```json
{
  "head_scale": 2.0,
  "neck_scale": 0.8,
  "spine_scale": 0.5,
  "upper_arm_scale": 0.6,
  "forearm_scale": 0.6,
  "thigh_scale": 0.7,
  "shin_scale": 0.7
}
```

変換式は次のとおりです。

```text
actual_bone_length = normalized_bone_length × scale_factor
```

例えば、歩行モーションの基準ボーン長を次のように定義します。

```json
{
  "upper_arm": 120,
  "forearm": 100
}
```

2頭身の倍率`0.6`を適用すると、実際のボーン長は次の値になります。

```text
upper_arm = 120 × 0.6 = 72
forearm   = 100 × 0.6 = 60
```

## 頭身比を利用する補助計算

単純な倍率ではなく、変換元と変換先の頭身から共通のボディ倍率を導出する場合は、次の式を使用します。

```text
target_ratio = target_heads / source_heads
```

7頭身から2頭身へ変換する場合です。

```text
target_ratio = 2 / 7
             = 0.2857
```

頭は2頭身側で相対的に大きく表示したいため、頭のみ逆方向に拡大します。

```text
head_scale = 1 / target_ratio
```

計算結果です。

```text
head_scale = 3.5
body_scale = 0.28
```

頭身比から得た値は初期値として使用し、胴体、腕、脚の個別倍率をBody Styleで補正します。

## KImageGraphでの最終推奨構成

```text
Motion
    ↓
Normalized Skeleton
    ↓
BodyStyle
    ↓
Bone Scaling
    ↓
IK Solve
    ↓
Full Skeleton
    ↓
DWPose PNG
```

Bone Scalingで頭身に応じた骨長を決定し、その後にIK Solverで足元や手先の目標位置を満たすよう補正します。

この方式なら、次の体型でWalk、Run、Attackなどの同じモーションを共有できます。

```text
2頭身
3頭身
4頭身
7頭身
モンスター体型
```

UnityのHumanoidリターゲットに近い考え方であり、モーションとボーン比率を分離して管理したいKImageGraphの設計と相性が良くなります。

### 各ボーンの変換

正規化テーブルの倍率を、ボーンごとに適用します。

```text
L' = L × Scale
```

例えば、UpperArmの基準長が`120px`で2頭身の倍率が`0.50`の場合です。

```text
UpperArm = 120px
120 × 0.50 = 60px
```

## 頭位置の計算

頭頂から足裏までの全高を`H`とすると、指定した頭身数に含まれる1頭分の高さを計算できます。

### 7頭身

```text
head_height = H / 7
```

### 2頭身

```text
head_height = H / 2
```

全高を`800px`とすると、各頭高は次の値になります。

```text
7頭身: 800 / 7 ≒ 114px
2頭身: 800 / 2 = 400px
```

同じキャンバス高さで比較すると、2頭身では頭が占める割合が大きくなるため、体幹と脚の骨長を短くして収めます。

## 各頭身の合計値を検算する

先に示したボーン倍率は、7頭身の骨長を基準に見た目を調整する係数です。
そのため、倍率を単純に合計しても目標の頭身数にはなりません。

## 身長比率による計算

より拡張性を高くするには、頭身をボーン倍率ではなく、全身の割合として管理します。

```csv
BodyStyle,HeadRatio,TorsoRatio,LegRatio
7Head,0.143,0.357,0.500
6Head,0.167,0.350,0.483
5Head,0.200,0.340,0.460
4Head,0.250,0.300,0.450
3Head,0.333,0.267,0.400
2Head,0.500,0.200,0.300
```

目標身長`H`から、各領域のサイズを計算します。

```text
head_height  = H × HeadRatio
torso_height = H × TorsoRatio
leg_height   = H × LegRatio
```

各比率の合計は`1.0`です。
比率表を使用すると、2.5頭身、3.5頭身、4.5頭身などの中間値も補間して追加しやすくなります。

## KImageGraphでの拡張可能な構成

```text
Normalized Motion
    ↓
BodyStyle: Head Count
    ↓
Bone Length Solver
    ↓
Skeleton
```

Body Styleでは見た目調整用の倍率と、合計頭身を保証する比率を分けて保持します。

- ボーン倍率：頭の大きさ、肩幅、腕のスタイルを調整
- 身長構成比：頭身数、頭・胴体・脚の高さを保証
- Bone Length Solver：目標身長から各ボーンの実長を計算

この構成にすると、共通モーションを維持しながら、整数頭身だけでなく小数頭身やモンスター体型にも展開できます。

### KImageGraphでの利用

```text
Motion
    ↓
Normalized Skeleton
    ↓
BodyStyleLoader
    ↓
BodyStyleRatio.csv
BoneStyle.csv
    ↓
SkeletonConverter
    ↓
FullSkeleton
    ↓
DWPoseRenderer
```

BodyStyleLoaderは指定された`BodyStyle`の行を両方のCSVから検索し、SkeletonConverterへ渡します。

```text
head_height  = target_height × HeadRatio
torso_height = target_height × TorsoRatio
leg_height   = target_height × LegRatio
```

その後、各ボーンにBoneStyle.csvのスケールを適用します。

```text
actual_bone_length = solved_bone_length × BoneScale
```

この構成にすると、次のモーションを1セット作成するだけで済みます。

```text
Walk
Run
Attack
Jump
```

同じモーションを次のBody Styleへ自動変換できます。

```text
2頭身
3頭身
4頭身
5頭身
6頭身
7頭身
```

特に2～5頭身のRPGスプライト制作では、モーション、身長比率、見た目調整を個別に管理できるため、キャラクター追加時の作業を減らせます。

    ↓

    ↓

```text
4.25HeadRatio
    = lerp(4.0HeadRatio, 4.5HeadRatio, 0.5)
```
