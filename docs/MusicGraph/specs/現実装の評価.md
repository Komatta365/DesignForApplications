現在のK-Music-Graphの設計は、一般的なノードベースDAWというより、ゲームの状態に応じて音楽を再構成する「インタラクティブミュージックエンジン」として独自性があります。

単なるAbleton、Cubase、Logicの代替を目指すのではなく、Wwise、FMOD、ComfyUI、Unreal Blueprintの特性を組み合わせた方向が適しています。

## 総合評価

| 分野 | 評価 | コメント |
|------|------|----------|
| Timeline | ★★★★★ | ゲーム中の楽曲区間と時間管理に適している |
| Theory | ★★★★★ | スケール、調性、コード進行を扱える |
| Composition | ★★★☆☆ | Melody Generatorへの依存が強い |
| Performance | ★★★★★ | ノードで演奏表現を制御できる |
| Instrument | ★★★★★ | MIDIと音源の役割を分離できる |
| Audio Effect | ★★★★★ | Reverb、Delay、EQなどを直列に接続できる |
| Mixer | ★★★★★ | 複数トラックと最終ミックスを管理できる |
| Parameter | ★★★★★★★ | 他のノードへゲームパラメータを接続できる |
| Utility | ★★★★★ | 補助的な処理をノードとして追加できる |
| Output | ★★★★★ | MIDI、WAV、MP3、OGGへ出力できる |

現在の設計は総合して高い完成度ですが、Composition層の分解が主な改善点です。

## 最大の課題

現在の基本構成では、メロディ生成が単一ノードに集中しやすくなっています。

```text
Scale
  ↓
Melody Generator
  ↓
NoteSequence
```

この構成では、AIがコードやスケールに適合するだけの音を並べ、次のような単調なメロディになる可能性があります。

```text
ド レ ミ ファ ミ ファ ソ ラ
```

K-Music-Graphでは、Composition層を次の工程へ分割します。

```text
Scale / Chord Progression
  ↓
Motif
  ↓
Phrase
  ↓
Variation
  ↓
Counter Melody
  ↓
NoteSequence
```

## Composition層の強化

### Motif

最初に4～8音程度の短いフレーズを生成します。

```text
Scale
  ↓
Motif
  ↓
C D G E
```

Motifは楽曲を特徴付ける識別子として機能し、展開や変奏の基点になります。

### Phrase

Motifを複数小節へ展開し、楽曲区間としての構造を作ります。

```text
Motif
  ↓
Phrase
  ↓
A → A' → B → A
```

単純な繰り返しではなく、終止位置やコード進行に応じた小さな変化を含めます。

### Variation

元のモチーフを維持しながら、変奏を追加します。

| 方式 | 例 |
|------|----|
| Transpose | C D G E → D E A F# |
| Invert | C D G E → C A# F G |
| Retrograde | C D G E → E G D C |
| Rhythm | リズム配置だけを変更 |
| Random | 制約付きのランダム変化 |

変奏を適用する箇所や強度は、Section、Mood Curve、Parameterから制御します。

### Counter Melody

主旋律に対する対旋律を生成します。

```text
Main Melody
  ↓
Counter Melody Generator
```

例：

```text
主旋律: C D E G
対旋律: G F E C
```

対旋律はゲームBGMの厚みを決める重要な要素です。Strings、Pad、Synthなどの伴奏より前に、主旋律との関係として生成します。

### Harmony Generator

コード進行は和音構造を決定しますが、Pad、Strings、Choirなどの声部配置は別途生成する必要があります。

```text
Chord Progression
  ↓
Harmony Generator
  ├─ Pad
  ├─ Strings
  └─ Choir
```

Harmony Generatorでは、ボイシング、転回形、声部間の音程、コード外音、音域を制御します。

## SectionとCompositionの連携

既存のSectionをCompositionの入力へ使用します。

```text
Intro → A → B → C → Loop → Outro
```

Sectionごとに利用するモチーフと変奏を指定します。

```text
Intro
└─ Motif 1

A
└─ Motif 1

B
└─ Motif 1 + Variation

C
└─ Motif 2
```

これにより、同じ素材から曲全体の変化を構成でき、イベントに応じて任意のSectionへ移動しやすくなります。

## Parameterを音楽構造へ接続する

K-Music-Graphの最大の強みは、ゲームパラメータを単なる音量調整ではなく、作曲処理へ直接接続できる点です。

通常の制御例：

```text
Danger
  ↓
Volume
```

K-Music-Graphでは、パラメータをコード進行やメロディ構造へ接続します。

```text
Danger
  ├─ Chord Progression
  ├─ Melody Variation
  ├─ Harmony Density
  └─ Note Range
```

例えば、Dangerの値に応じて和音を変化させます。

```text
Danger = 0
  ↓
I - V - vi - IV
  ↓
平和

Danger = 100
  ↓
i - bII - dim7 - vii°
  ↓
不安
```

また、Melody Variationへ接続することで、緊張度に応じた音数と跳躍を制御できます。

```text
Danger = 0
  ↓
音数が少ない / 跳躍が少ない

Danger = 100
  ↓
音数が増加 / 跳躍が増加
```

Parameterから影響を受ける対象：

| Parameter | 変更対象 |
|-----------|----------|
| Danger | コード進行、変奏量、音符密度、跳躍 |
| BattleLevel | Section、テンポ、対旋律の強度 |
| Tension | 不協和音、Velocity、オーケストレーション |
| Energy | 音域、トラック数、リズム密度 |
| Progress | Motif、Phrase、Sectionの進行 |

## Transitionノード

ゲームではTown、Battle、Bossなどの状況切り替えが頻繁に発生します。Transitionノードは、現在と次のSectionを受け取り、自然な接続区間を作成します。

```text
Parameter: BattleLevel
  ↓
Transition
  ↓
Section
```

推奨する切り替え方式：

| 方式 | 用途 |
|------|------|
| 次の小節頭で切り替え | リズムを維持した場面転換 |
| フィルを挿入して切り替え | 戦闘開始など強い変化 |
| コードブリッジ | 調性やテンポを段階的に変更 |
| レイヤークロスフェード | 同一構造の強度変化 |
| 即時切り替え | 緊急イベントや演出 |

Transitionは、MIDI段階で小節・拍・コードを判断できるため、音声ファイルをクロスフェードするだけの方式より柔軟です。

## AIによるノードグラフ生成

AIには完成した音符を作らせるのではなく、楽曲を構成するノードグラフを生成させます。

ユーザー入力：

```text
和風の町BGM
```

AIが生成する高レベルグラフ：

```json
{
  "nodes": [
    { "type": "song", "bpm": 90 },
    { "type": "key", "value": "D Major" },
    { "type": "scale", "value": "Japanese" },
    { "type": "chordProgression", "value": ["I", "V", "vi", "IV"] },
    { "type": "motif", "style": "Traditional" },
    { "type": "instrument", "value": "Koto" },
    { "type": "instrument", "value": "Shamisen" },
    { "type": "reverb", "preset": "Hall" }
  ]
}
```

その後、Rust Coreが次の工程を実行します。

```text
Motif
  ↓
Phrase
  ↓
Variation
  ↓
NoteSequence
```

AIはノードの種類、ジャンル、雰囲気、楽器、構造などの高レベル条件を担当し、Rust Coreは音楽理論、制約、再現可能な音符生成を担当します。

## 追加を推奨するノード

ゲームBGM向けに、次の5ノードを優先して追加します。

| 優先度 | ノード | 役割 |
|--------|--------|------|
| 1 | Motif | 曲の核となる短いフレーズを作る |
| 2 | Phrase | Motifを複数小節へ展開する |
| 3 | Variation | 移調、反行、逆行、リズム変化を行う |
| 4 | Counter Melody | 主旋律と協調する対旋律を生成する |
| 5 | Transition | ゲーム状態に合わせてSectionを自然に切り替える |

追加実装の推奨順序：

1. Motifデータ構造と生成ルールを定義する
2. Phrase Generatorを実装する
3. Variation Generatorを実装する
4. Counter Melody Generatorを実装する
5. Harmony Generatorを追加する
6. Parameterから各生成ノードを制御する
7. Section間のTransitionを実装する

## 現在の評価と目標

現状の完成度は高く、Timeline、Theory、音源、エフェクト、ミキサー、Parameter、出力機能の基礎は整理されています。残る主な課題は、Compositionを「Melody Generator一発」から作曲工程へ分解することです。

```text
Melody Generator一発
  ↓
Motif
  ↓
Phrase
  ↓
Variation
  ↓
Counter Melody
  ↓
Transition
```

この強化により、K-Music-Graphは単調な自動作曲ツールではなく、ゲームイベントとParameterに応じて楽曲構造を変化させるミュージックエンジンになります。
