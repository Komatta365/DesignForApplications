AI作曲では、LLMへ「ファンタジー風のBGMを作って」と直接依頼すると、コード進行に沿った単調な音階しか生成されないことがあります。

```text
C - G - Am - F

ド レ ミ ソ
ミ ソ ラ ド
```

これは、LLMが音楽理論に基づいて音符を構築するというより、入力に続くテキストを予測することが主な処理になるためです。単独のメロディ生成ではなく、作曲工程をノードへ分割し、AIとルールベース処理の役割を明確にします。

## 解決策1: Melody Generatorを分割する

従来の構成：

```text
Chord
  ↓
Melody Generator
  ↓
MIDI
```

モチーフ、フレーズ、対旋律、変奏、演奏表現を分離した構成：

```text
Chord
  ↓
Motif Generator
  ↓
Phrase Generator
  ↓
Counter Melody Generator
  ↓
Variation Generator
  ↓
Humanizer
  ↓
MIDI
```

### Motif Generator

最初に2～4小節の短いモチーフを作ります。短いフレーズはLLMでも比較的一貫した生成が期待できます。

```text
C E G E
```

出力では、単なる音名列だけでなく、音長、速度、強弱も保持します。

```json
{
  "bars": 2,
  "notes": [
    { "pitch": 60, "duration": 1.0, "velocity": 80 },
    { "pitch": 64, "duration": 1.0, "velocity": 84 },
    { "pitch": 67, "duration": 1.0, "velocity": 88 },
    { "pitch": 64, "duration": 1.0, "velocity": 76 }
  ]
}
```

### Phrase Generator

モチーフを繰り返すだけでなく、コード進行やキーに合わせて展開します。

```text
C E G E
  ↓
C E G E
D F A F
E G B G
G B D B
```

コードトーン、ノンダイアトニックノートの使用条件、フレーズ終止位置はRust Harmony Engine側で検証します。

### Counter Melody Generator

初心者向けの生成では主旋律しかない構成になりがちです。主旋律を入力として、リズムや音域を補完する対旋律を生成します。

```text
主旋律: C D E G
対旋律: G F E C
```

対旋律では、次の制約を設定します。

- 主旋律と同じピッチを長時間重ねない
- コードトーンとの不協和を管理する
- 主旋律とは異なるリズムを持たせる
- オクターブや音域を調整して声部を分離する

### Variation Generator

同じモチーフの再利用に対して、構造的な変化を加えます。AI作曲が単調になるのを防ぐ必須ノードです。

#### 転回

```text
C E G
  ↓
G C E
```

#### リズム変化

```text
四分音符・四分音符・四分音符・四分音符
  ↓
四分音符・八分音符・八分音符・四分音符
```

#### オクターブジャンプ

```text
C D E F
  ↓
C D E C'
```

#### 装飾音

```text
E
  ↓
D E
```

変化量は、楽曲の盛り上がりや指定ジャンルに応じて制御します。変奏しすぎると元のモチーフが失われるため、各フレーズで変化対象を制限します。

### Humanizer

完全に等間隔・等強度なMIDIは機械的に聞こえます。Humanizerは、作曲内容を変えずに演奏表現を追加します。

| パラメータ | 例 |
|----------|----|
| Timing | 発音位置を前後数ミリ秒ずらす |
| Velocity | 音符の強弱を調整する |
| Gate | 音長をわずかに変化させる |
| Articulation | レガート、スタッカートを適用する |

## 解決策2: 感情カーブを持たせる

BGM全体にストーリーを与えるため、Mood Curveノードで時間ごとの感情と強度を定義します。

```text
開始
  ↓
期待
  ↓
盛り上がり
  ↓
クライマックス
  ↓
落ち着く
```

Mood Curveの出力例：

```json
[
  { "bar": 0, "energy": 0.3 },
  { "bar": 16, "energy": 0.6 },
  { "bar": 32, "energy": 1.0 },
  { "bar": 48, "energy": 0.4 }
]
```

エネルギー値は、次のパラメータへ反映します。

| 生成要素 | Energyが高い場合の例 |
|----------|----------------------|
| 音符密度 | リズムと装飾音を増やす |
| 音域 | より高い音域を利用する |
| 跳躍 | オクターブ移動を許可する |
| 声部数 | 対旋律やハーモニーを追加する |
| 楽器 | ドラム、ブラス、ストリングスを増やす |
| ダイナミクス | Velocityとミックスレベルを上げる |

曲全体で単調なモチーフを使う場合でも、Mood Curveによって展開に緩急を付けられます。

## 解決策3: AIに直接MIDIを書かせない

AIからMIDIノートを直接大量生成すると、拍、キー、コードとの整合性や再現性を保証しにくくなります。

悪い構成：

```text
AI
  ↓
MIDI生成
```

推奨構成：

```text
AI
  ↓
作曲ルール・高レベル条件
  ↓
Rust Engine
  ↓
MIDI生成
```

AIには、次のような抽象的な条件だけを生成させます。

```text
テンション: 高
アルペジオ: 多め
跳躍: あり
主要楽器: ストリングス
```

実際の音符配置は、Rust Harmony Engineが次の規則を検証しながら行います。

- キーと調号
- コードトーン
- 小節内の拍と拍子
- 不協和音の解決
- 音域と楽器の演奏可能範囲
- 前後フレーズとの連続性
- 出力形式と再現性

LLMの出力は数値と制約を含む構造化データとし、自由形式の自然言語をMIDIへ直接変換しない設計にします。

## 解決策4: フレーズライブラリを持つ

RPGのようにジャンルや場面が明確な用途では、既知のモチーフをライブラリ化します。

```text
Fantasy
├─ Field
├─ Town
├─ Battle
├─ Boss
└─ Victory
```

各カテゴリに複数のモチーフを登録し、AIには自由生成ではなく、選択と組み換えを担当させます。

```text
AI入力
  ↓
カテゴリ・感情・楽器の判定
  ↓
モチーフ検索
  ↓
候補の選択・組み換え
  ↓
Phrase / Variation Generator
```

ライブラリには次のメタデータを持たせます。

```json
{
  "id": "fantasy-field-001",
  "genre": "fantasy",
  "scene": "field",
  "mood": "calm",
  "key": "D minor",
  "bars": 4,
  "energy": 0.4,
  "tags": ["strings", "flute", "nature"]
}
```

## KMusicGraphで推奨する構成

```text
Genre / Key / Mood
  ↓
Chord Generator
  ↓
Motif Generator
  ↓
Phrase Generator
  ↓
Counter Melody Generator
  ↓
Variation Generator
  ↓
Humanizer
  ↓
MIDI
```

Counter Melody GeneratorとVariation Generatorは、単調なAI作曲を避けるための必須ノードです。感情カーブは各ノードの生成量や演奏表現へ影響を与えます。

```text
Mood Curve ─────────────────────────┐
                                    ↓
Chord → Motif → Phrase → Counter → Variation → Humanizer → MIDI
```

## 実装方針

KMusicGraphでは、Motifノード内のみをLLM生成にし、最終的な楽曲構築をRust Coreで行う構成が、品質と再現性のバランスに優れます。

| 処理 | 推奨実装 | 責務 |
|------|----------|------|
| モチーフ候補生成 | LLM | 短いフレーズや選曲条件の生成 |
| モチーフ検索 | ライブラリ / ベクトル検索 | 既存素材から候補を選択 |
| コード進行 | Rust Harmony Engine | 和声規則に沿った進行を生成 |
| フレーズ展開 | Rust Harmony Engine | モチーフをコード進行へ展開 |
| 対旋律・変奏 | Rust Core | 制約を守った音符生成 |
| 演奏表現 | Humanizer | Timing / Velocity / Gateの調整 |
| MIDI出力 | Rust MIDI Engine | 再現可能なMIDI生成 |

最終目標は、次の工程をノードとして分離することです。

```text
モチーフ生成
  ↓
展開
  ↓
変奏
  ↓
対旋律
  ↓
演奏表現
  ↓
MIDI
```

この工程分割により、「それらしいが単調」なAI作曲ではなく、楽曲構造と再現性を保ったゲームBGMを生成できます。
