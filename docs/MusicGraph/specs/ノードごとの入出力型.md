K-Music-Graphでは、ノード間をMIDIやAudioだけで接続せず、意味のある型を持つポートで接続します。型付きポートにより、ノード編集時に互換性を検証し、接続後の実行エラーを減らします。

基本方針：

- すべてのポートにデータ型を設定する
- 異なる型を暗黙変換しない
- 変換が必要な場合は変換ノードを明示する
- 同じ概念の入力と出力には共通型を使用する
- ゲーム状態をCompositionへ接続できる型を用意する

## 基本ポート型

```typescript
type PortType =
  | "SongData"
  | "SectionData"
  | "KeyData"
  | "ScaleData"
  | "ChordData"
  | "ChordProgressionData"
  | "MotifData"
  | "PhraseData"
  | "HarmonyData"
  | "NoteData"
  | "NoteSequence"
  | "RhythmData"
  | "ParameterData"
  | "MoodData"
  | "EnergyData"
  | "ArrangementData"
  | "TransitionData"
  | "MidiData"
  | "AudioData"
  | "TriggerData"
  | "Float"
  | "Bool"
  | "Any";
```

`Any`はSwitchなど、実行時に選択された入力型をそのまま通すノード向けです。通常の音楽ノードでは使用せず、型付き接続を維持します。

## 型の階層

```text
SongData
└─ SectionData
   └─ ArrangementData

KeyData
└─ ScaleData
   ├─ ChordData
   └─ ChordProgressionData
      └─ HarmonyData

MotifData
└─ PhraseData
   └─ NoteSequence
      ├─ MidiData
      └─ Instrument → AudioData
```

階層の概念は変換関係を示すものです。同じ型へは直接接続でき、別の型へ渡す場合は対応する生成・変換ノードを使用します。

## Timeline

### Song

```text
Output: SongData
```

```typescript
interface SongData {
  bpm: number;
  timeSignature: [number, number];
  lengthBars: number;
  loop: boolean;
}
```

Songは楽曲全体の基本情報を提供します。

### Section

```text
Input:  SongData
Output: SectionData
```

```typescript
interface SectionData {
  name: string;
  startBar: number;
  endBar: number;
}
```

SectionはIntro、A、B、C、Loop、Outroなどの区間を表します。

## Theory

### Key

```text
Output: KeyData
```

```typescript
interface KeyData {
  root: string;
  mode: string;
}
```

`mode`にはMajor、Minorなどの調性を指定します。

### Scale

```text
Input:  KeyData
Output: ScaleData
```

```typescript
interface ScaleData {
  root: string;
  notes: number[];
}
```

`notes`はMIDIノート基準のピッチクラスを表します。

### Chord

```text
Input:  KeyData
Output: ChordData
```

```typescript
interface ChordData {
  root: string;
  type: string;
  notes: number[];
}
```

`type`にはMaj7、min7、dimなどのコード種別を指定します。

### Chord Progression

```text
Input:  KeyData
Output: ChordProgressionData
```

```typescript
interface ChordProgressionData {
  chords: ChordData[];
}
```

必要に応じて各コードの開始拍や継続拍数を追加しますが、順序付きのChordData配列を基本とします。

## Composition

Composition層では、`PhraseData`を主要な受け渡し型として利用します。

### Motif

```text
Input:
  - ScaleData
  - ChordData
Output:
  - MotifData
```

```typescript
interface MotifData {
  notes: NoteData[];
}
```

### Phrase

```text
Input:  MotifData
Output: PhraseData
```

```typescript
interface PhraseData {
  notes: NoteData[];
  bars: number;
}
```

### Variation

```text
Input:  PhraseData
Output: PhraseData
```

```typescript
interface VariationSettings {
  transpose: number;
  inversion: boolean;
  retrograde: boolean;
}
```

VariationSettingsはノードの設定値であり、入出力ポートではなく、PhraseDataを受け取って変化後のPhraseDataを返します。

### Sequence Generator

```text
Input:  PhraseData
Output: PhraseData
```

入力フレーズの音型を段階的に移動し、反復フレーズを生成します。

### Counter Melody

```text
Input:
  - PhraseData
  - ChordProgressionData
Output:
  - PhraseData
```

主旋律とコード進行を基に、対旋律のPhraseDataを生成します。

### Harmony Generator

```text
Input:  ChordProgressionData
Output: HarmonyData
```

```typescript
interface HarmonyData {
  voices: NoteSequence[];
}
```

### Ostinato

```text
Input:  ChordProgressionData
Output: PhraseData
```

コード進行に合わせて繰り返し音型を生成します。

### Ornament

```text
Input:  PhraseData
Output: PhraseData
```

### Call & Response

```text
Input:  PhraseData
Output: PhraseData
```

### Transition

```text
Input:
  - PhraseData
  - PhraseData
Output:
  - TransitionData
```

```typescript
interface TransitionData {
  phrase: PhraseData;
  targetSection: string;
  startBeat: number;
  endBeat: number;
}
```

Transitionの音符だけを後続処理へ渡す場合はPhraseDataへ変換しますが、移動先と時間情報を保持するため、標準出力はTransitionDataとします。

### Density Control

```text
Input:
  - PhraseData
  - Float
Output:
  - PhraseData
```

### Adaptive Melody

```text
Input:
  - PhraseData
  - EnergyData
  - ParameterData
Output:
  - PhraseData
  - ArrangementData
```

ParameterDataだけに依存せず、変換済みのEnergyDataを受け取ることで、作曲側がゲーム固有の変数名を知らずに処理できるようにします。


|--------|------|------|
| Reverb | AudioData | AudioData |
| Delay | AudioData | AudioData |
| EQ | AudioData | AudioData |
| Compressor | AudioData | AudioData |
| Limiter | AudioData | AudioData |

## ゲーム状態から作曲への経路

通常の音楽処理経路：

```text
Theory
  ↓
Composition
  ↓
NoteSequence
  ↓
Instrument
  ↓
AudioData
```

ゲーム状態からCompositionを制御する副経路：

```text
ParameterData: Danger
  ↓
EnergyData
  ↓
Adaptive Melody
  ↓
Composition
```

Dangerの変化例：

```text
Danger = 0
  ↓
EnergyData = 低
  ├─ 音数を減らす
  ├─ 跳躍を減らす
  └─ 安定したコードを選ぶ

Danger = 100
  ↓
EnergyData = 高
  ├─ 音数を増やす
  ├─ テンションコードを増やす
  ├─ 跳躍を増やす
  └─ Counter Melodyを追加する
```

ゲーム側の変数名をCompositionノードへ直接渡すのではなく、`ParameterData → EnergyData / MoodData / ArrangementData`の変換層を挟みます。これにより、作曲ノードをゲーム以外の入力にも再利用できます。

## 型安全な接続ルール

1. 出力ポート型と入力ポート型が一致する場合だけ直接接続する
2. 配列型は単一型と別の型として扱う
3. NoteSequenceとAudioDataは暗黙変換しない
4. MusicData系の変換はCompositionノードで行う
5. AudioDataの変換はInstrumentまたはAudio Effectノードで行う
6. ParameterDataから作曲制御値への変換は専用のMappingノードで行う
7. `Any`を持つノードは接続時に実際の型へ解決する
8. 実行前にグラフ全体を検証し、未接続の必須入力をエラーにする
